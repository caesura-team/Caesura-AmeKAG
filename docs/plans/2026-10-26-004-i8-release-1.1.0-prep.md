## 2. CHANGELOG 草案

- 草案位置：`CHANGELOG.md` 顶部 `## [Unreleased]`，条目人工归类为 Added / Changed / Fixed，并保留代表提交短 SHA；未逐提交复制预览，未臆造条目。
- 生成方式（本任务只做预览，不写盘）：`python scripts/gen_changelog.py --from-tag v1.0.1 --tag 1.1.0 --dry-run`，范围 `v1.0.1..HEAD` 共 797 commits，预览输出 840 行 / 124,180 字节，分组统计 Feat 113、Fix 215、Perf 7、Refactor 7、Test 88、Docs 276、Build 3、Ci 31、Chore 16、Merge 4、Plan 7、Other 30。

## 4. 发布链当前事实（只读核对）

- `.github/workflows/release.yml`（候选 `e4e40be2` 的文件）名称是 **Release input dry-run**；触发仅两种：`push: tags: v*` 与 `workflow_dispatch: inputs.version`（“Existing tag matching this source; verifies inputs without publishing”）。
- job 结构：`Lock source and candidate policy`（prepare）→ `Validate engine`（复用 `validate-engine.yml`，10 个必需 producer job）→ `Verify release inputs`（aggregate）；run 展开为 12 个 job。workflow 内**没有** release 上传、Pages 上传或部署 job；文件首行注明 “U23 dry-run only. No release upload, Pages upload or deployment is authorized by this workflow.”
- 版本/标签硬约束（`scripts/prepare_release_policy.py`）：从 `CMakeLists.txt` 解析唯一 engine version，并要求 `release_tag == "v" + version`，否则报 “Release tag differs from engine version”；包期望文件名由 `{version}` 展开（`scripts/release_input_policy.json` 的 `required_files`），因此 1.1.0 的包名会是 `CaesuraAmeKAG-1.1.0-*.zip/.tar.gz/.dmg/...`。workflow 另要求 tag 为数字版本（正则 `v[0-9]+(?:\.[0-9]+){2,3}`）且解析到本次运行 source commit。
- 现状：`v1.0.1` 指向 `9aa299d4`（2026-08-21），与本轮候选 `e4e40be2` 不匹配；只读回读 `gh run list --workflow release.yml --limit 10` 为空——`release.yml` 从未运行，hosted tag-triggered dry-run 仍为 **NOT_RUN**。
- GitHub release 现状：`gh release list` 仅显示 `v1.0.0` 与 `v1.0.1`；本轮未创建新 release。
- U31 已验收的候选 run 37195162558 的 aggregate 为 `DRY_RUN_INPUTS_VERIFIED` / `INPUTS_VERIFIED` / `HOSTED_INPUTS_VERIFIED` 且 `release_ready=false`；即使未来 dry-run 绿色也不授权发布。

## 5. dry-run 执行前提与预期（未执行）

完整可复制说明见 [release-process §6.2](../guides/release-process.md#62-release-input-dry-run-tag-triggered-no-publish)。摘要：

1. G1：bump `CMakeLists.txt` VERSION 并命名 `CHANGELOG.md` 节，提交到 `master`（不 tag）。
2. G2：在发布 commit 上创建 annotated tag（例 `v1.1.0`），`git push origin v1.1.0` 触发 “Release input dry-run”；或 `gh workflow run release.yml -f version=v1.1.0`（输入必须是现存且匹配 source 的 tag）。
3. 预期 run：12 个 job；产物为 10 个 producer 的执行证据（`u23-*`）、最终包（`caesura-amekag-*`、`android-release-artifacts`、`android-slices`、`caesura-pages-*`）、包证据（`u22-*-package-evidence`）与 `release-input-gate-evidence`；aggregate 必须为 `DRY_RUN_INPUTS_VERIFIED` 且 `release_ready=false`；不创建 release、不上传 release asset、不部署 Pages。
4. 失败回滚：失败 run 与原始 artifact 保留，不用绿色重试抹除；**不移动已有 tag**；如需重跑，记录后删除刚推送的 tag（仅当其未被外部引用）或在 G1 后提升版本、在新发布 commit 上重打 tag；`v1.0.1` 等历史 tag 不得改写；误用 `gh release create` 的清理属 G3 动作。
