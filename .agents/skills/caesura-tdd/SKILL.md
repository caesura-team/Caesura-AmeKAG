# Caesura 测试驱动实现
先从当前源码和已有测试找真实执行路径，读取相关 docs/solutions。无必要的文档/配置文字修改不编写镜像实现的测试。
1. 建立能观察用户行为或所有权的最小回归，先运行未修实现，保存原始失败。若问题被反证，记录而不制造补丁。
2. C++ 用 doctest及同一生产静态库；Lua 用实际 tokenizer/compiler/scheduler/runner；Web 复用 Vitest/Wasmoon。只在宿主边界替身，不替换要证明的被测逻辑。
3. 异步测试采用 barrier、可控完成时机和新请求正控制；不能用随机 sleep 假装覆盖竞态。
4. 最小实现后运行相关回归，保持负控制仍能失败。失败时修根因；只有测试前提确错才修改测试。
5. 新 Lua 文件注册实际执行入口、沙箱 preload 与 Web 索引；主/隔离套件不能混合。
6. 整合后执行适用完整门禁，记录源/配置/产物/日志身份。过滤未选中项不是完整套件跳过。
覆盖率只报告真实工具结果；高风险改动争取相关代码行/分支不少于80%，达不到或无法测量时说明具体缺口，不用注册数冒充。
